A familiar idea, a different view

MVU structure.
Room for the browser.

01

Model the application’s decisions

Use Gleam’s types for shared data, meaningful state, and pure updates. Let the browser keep local details such as focus, selection, and drafts that only matter on submit.

02

Views stay close to the web

Use lit-html’s HTML-like templates, element properties, DOM events, and native controls. Work with the platform directly, using regular CSS or the tools you already know.

03

Work has a place in the loop

The runtime handles the loop, effects, subscription lifetimes, and cleanup. Your app chooses how to handle forms, dialogs, routing, and the rest.

An alternative, by design

Like MVU, but prefer writing templates?

Glimlit is for developers who enjoy the Model–View–Update approach of Elm and Gleam frameworks such as Lustre, and want another option for authoring views. It combines Gleam’s state model with lit-html rather than expressing every element as a Gleam function call.
